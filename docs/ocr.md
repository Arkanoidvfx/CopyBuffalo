# Локальный OCR CopyBuffalo

Уточнение 19 октября 2026: перевод теперь создаёт **изображение с русскими надписями**, а не текстовую запись. `OcrText.Result` сохраняет размеры и отдельные OCR-области; `TranslatedImage` подбирает фон/чернила, вписывает Plex на место надписи и сохраняет исходный размер. Слишком длинная, пропущенная или пустая надпись отклоняет всю операцию. Неизменившиеся строки сохраняются, оригинал остаётся в истории. Скопированный результат содержит PNG и bitmap с OwnFormat и защитой от нового пользовательского копирования; расшифровка/декодирование идут вне UI-потока. Успех показывается компактно на две секунды. Однотонный фон поддерживается лучше сложных текстур: генеративного восстановления под буквами нет.

Финальная Release/ReadyToRun прошла 317 проверок и живой сквозной прогон, включая маленькие тёмные Events / Server Boosts, сохранение значков, зашифрованное хранение картинки и PNG/bitmap payload без текста. Логи, PNG и rollback: `.tmp/image-overlay/`. `publish/` обновлён с проверкой 363 файлов по SHA256, приложение перезапущено через Explorer. Реальный буфер, ввод и фокус при проверках не использовались; установщики не пересобирались.

19 октября 2026: прямые кнопки OCR и перевода доступны в истории, закреплённом списке и плитках. `TranslateImageRequested` использует общий `App.ProcessImage`: расшифровка → OCR с координатами → `PromptCompressor.TranslateRegionsAsync` → `TranslatedImage.Render` → новое изображение → сохранение → условное копирование PNG/bitmap. Состояние `Recognizing` блокирует обе кнопки до конца операции, InfoBar показывает фазу и отмену. `GenerateAsync` общий со сжатием: очередь, проверка полного непустого ответа, отмена загрузки/HTTP и остановка сервера в `finally`. Из Page2Language переиспользованы подходы локального перевода отдельных OCR-областей и подбора доминирующего фона/контрастных чернил по квантованным цветам; Chrome/native messaging не нужны. Проверка `--translation-selftest <dir>` использует синтетические картинки: отмена старта, повтор, живой перевод с числом/URL, отрисовка PNG, зашифрованная запись изображения и загрузка, а также маленькие тёмные подписи Events / Server Boosts. Точность перевода модели требует проверки пользователем.

Release/ReadyToRun прошёл 299 проверок. Живой тест использовал собственный зашифрованный PNG и весь путь OCR → перевод → зашифрованная история; число, URL, смысл тестовой инструкции и русский исходник сохранены. Проверено сжатие промптов на общем runtime. Логи и offscreen-превью: `.tmp/image-actions/`. Локальный `publish/` обновлён с SHA256-проверкой, приложение перезапущено через Explorer; установщики не пересобирались. Автоматические проверки не управляют мышью, клавиатурой, фокусом или реальным буфером; реальное положение у курсора на разных DPI и качество на пользовательских снимках остаются для ручной проверки.

Использование: Win+V → кнопка «Распознать текст» на изображении (либо пункт меню по правому клику). Результат сохраняется отдельной текстовой записью; исходное изображение остаётся. Автоматическое копирование допускается только при неизменившемся буфере и без новой вставки во время OCR. В InfoBar доступны отмена обработки и проверка результата в существующем редакторе. Панель можно скрыть: завершение обработки не открывает окно и не меняет фокус.

Движок — [pure-onnx-ocr 0.3.1](https://github.com/siska-tech/pure-onnx-ocr/tree/59a6c2c33c72e4dc8e7e5500f544d6674b0e6643), recognizer — [cyrillic_PP-OCRv5_mobile_rec_onnx](https://huggingface.co/PaddlePaddle/cyrillic_PP-OCRv5_mobile_rec_onnx/tree/2cef88145434beb8afa9dd82d77d799eb1ad7b29), detector — [PP-OCRv5_mobile_det_onnx](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_det_onnx/tree/e6f4fa85f00e168c862bc462aebca69eef9b3d3d). PP-OCRv6 small/medium не используются для русского текста. Ревизии, SHA256 и Cargo dependencies закреплены в `tools/ocr/Build-Ocr.ps1` и `tools/ocr/Cargo.lock`.

Изображение расшифровывается в фоновом потоке через существующий ImageFiles и поступает в скрытый `ocr/copybuffalo-ocr.exe` через stdin. Открытых временных PNG нет. Worker не использует сеть; библиотека и модели запускаются на CPU, четыре inference threads, BelowNormal priority. На каждое действие создаётся отдельный процесс, который завершается после результата; отмена/выход/падение приложения закрывает процесс через kill-on-close Job Object. Снимок байтов изображения обнуляется после обработки. Runtime не требует установленного Python, Rust или отдельно установленного Visual C++ runtime: CRT входит в worker.

Детектор сохраняет исходное разрешение до длинной стороны 2048 px, более крупные снимки уменьшает. До декодирования worker проверяет размеры: не больше 80 Мп и 128 МиБ закодированных данных. Приложение также соблюдает лимиты изображений и текста из настроек; результат сверх лимита не обрезается. JSON, геометрия, уверенность и размер ответа проверяются; ошибки не выводят распознанный текст в diagnostic logs. При удалении исходной записи незавершённый результат не публикуется. Буфер остаётся прежним при ошибке сохранения на диск.

OcrText строит порядок по координатам: вертикальные промежутки отделяют колонки, общие широкие заголовки/подвал обрабатываются отдельно, горизонтальные промежутки отделяют блоки, фрагменты одной строки собираются по X. Не требуется угадывать порядок по исходному порядку детектора. Таблица и несколько колонок текста могут иметь похожую геометрию — такой layout помечается для проверки.

Коррекция алфавита применяется внутри слова, когда один алфавит подтверждён буквами, не имеющими визуального двойника, а другой состоит только из таких двойников. Примеры: `СоруBuffalo` → `CopyBuffalo`, `imаgе_2026.png` → `image_2026.png`, `Pусский тeкст` → `Русский текст`. Чистые русские имена папок сохраняются. Неоднозначные сокращения `СОС`, действительно смешанные слова, расширенные кириллические двойники и низкая уверенность требуют проверки; словарь исключений и угадывание по соседним словам не используются.

На исходном синтетическом корпусе 11 октября (26 PNG, 160 строк: русский/английский/смешанный, Segoe UI/Consolas, 11/18 px, светлый/тёмный фон, две колонки) после коррекции общий raw CER снизился с 5,73% до 1,31%. Русский — 0,43%, английский — 0,34%; две колонки — 0% вместо 49,36%, смешанный текст в одной колонке — 3,48% вместо 8,46%, смешанный текст включая колонки — 2,92%. Исправлены 80 символов; 8 из 26 изображений отмечены для проверки. Эти цифры не гарантируют точность на реальных скриншотах. Медиана полной операции с отдельным процессом на Ryzen 7800X3D — 924 мс в финальной ReadyToRun-сборке со статическим CRT.

Сборка worker:

```powershell
pwsh -NoProfile -NonInteractive -File tools/ocr/Build-Ocr.ps1
```

Используется Rust/MSVC >=1.91, Cargo `--locked --jobs 2`, статический CRT, SHA256 моделей/архива, проектный cache и сохранённые dependency licenses. Публикация WPF автоматически включает `Assets/Ocr` в каталог `ocr/`; publish отклоняется без executable и моделей. Установщики core/full содержат один и тот же OCR-комплект.

Проверки: `--selftest` включает script corrections, ambiguous text preservation, русские пути, 2/3 колонки, шапку/подвал, фрагменты строки, confidence, JSON/размеры/геометрию, ограничение stdout, отказ пути вне images/, transient working state и offscreen вызов меню. `--ocr-selftest <corpus>` использует только синтетические PNG с `manifest.json`, дополнительно проверяет расшифровку собственного тестового файла, повреждённый вход, отмену/повтор и фактический pixel limit; результат пишет в `ocr-results.json`. `packaging/Test-Distribution.ps1` проверяет worker на собственном синтетическом снимке при PATH без системных .NET/FFmpeg.

Реальный ввод, приватная история и системный буфер при автоматических проверках OCR не используются. Live кнопка, большие/нечёткие/вращённые изображения, другие DPI, таблицы и точность реальных команд/путей остаются для ручной проверки. GPU backend не реализован.
