# CopyBuffalo: проверка pure-onnx-ocr, 11 октября 2026

Связка **pure-onnx-ocr 0.3.1 + PP-OCRv5 mobile detector + cyrillic PP-OCRv5 mobile recognizer работает на этой Windows-машине**. На синтетических одноколоночных изображениях она заметно точнее встроенного Windows OCR, но повторное распознавание примерно в 35 раз медленнее. Это полезный кандидат для будущего извлечения текста со скриншота по запросу пользователя; оснований для безусловного выбора пока недостаточно: остаются порядок колонок и подмена похожих букв разных алфавитов.

**В текущей рабочей копии CopyBuffalo OCR не реализован.** Имя папки и сборки — ArkCopyBuffer, Git remote — `https://github.com/Arkanoidvfx/CopyBuffalo.git`. Проверены tracked и untracked C#-исходники, проектные зависимости, README и инструкции `.agents/skills/arkcopybuffer-project/SKILL.md`: движок, OCR-команда и OCR-зависимость не найдены. Совпадения `System.Windows.Media` относятся к WPF, а не к `Windows.Media.Ocr`. Поэтому преимущество перед «текущим OCR приложения» измерить невозможно. Ниже Windows.Media.Ocr используется как **отдельный ориентир**, а не как существующая реализация CopyBuffalo.

Машина: Windows 11 Pro build 22631, Ryzen 7 7800X3D, 16 логических CPU, около 63,1 ГиБ доступной системе RAM, RTX 3090 24 ГиБ. Перед полным тестом свободно 21 761 МиБ VRAM. Для pure-onnx-ocr использован CPU backend; ускорения RTX 3090 здесь нет. Перед загрузкой/сборкой проверено свободное место: C 11,8 ГиБ, D 16,7 ГиБ. Загрузки, Cargo cache, temp и build размещены внутри экспериментальной папки.

Корпус — 26 PNG размером 960 × 320, 96 DPI, с эталонами в `corpus/manifest.json`. Полный набор: русский/английский/смешанный текст × Segoe UI/Consolas × 11/18 px × светлый/тёмный фон = 24 изображения; ещё два смешанных изображения с двумя колонками. Всего 160 эталонных строк, 5 288 символов с разделителями строк, 736 слов. Текст содержит Ё/ё/ъ/ы, цифры, пунктуацию, пути и сочетания клавиш. PNG отрисованы через System.Drawing, AntiAliasGridFit; текст не обрезан. Проверены фактические семьи шрифтов и сохранены SHA256 файлов шрифтов. Это синтетические растровые образцы, не реальные снимки интерфейсов.

На каждом изображении каждый движок запускается новым процессом, создаёт один engine и делает пять проходов. Четыре повторных прохода используют тот же engine. Всего 52 процесса и 260 проходов в основном сравнении. Очерёдность изображений перемешана с seed 20261011; движки запускаются попарно, первый в паре чередуется. Оба процесса получают affinity `0xF000` — четыре логических CPU — и BelowNormal priority; у pure-onnx-ocr дополнительно `inference_threads(4)` и `rec_batch_size(1)`. Прочие параметры штатные: detector long side 960, thresh 0.3, box_thresh 0.6, unclip 1.5, без warmup и orientation classifiers. Windows OCR получает en-US для английских примеров и ru-RU для русских/смешанных; это выбор по метке корпуса, не автоматическое определение языка.

«Первый проход» включает декодирование PNG и первую компиляцию inference plans у tract. Загрузка engine измерена отдельно. «Новый процесс» не означает сброс файлового кеша Windows. Фоновые программы пользователя продолжали работать; показатели относятся к согласованному щадящему режиму, а не к изолированному максимальному CPU benchmark.

CER — расстояние Левенштейна / число эталонных Unicode-символов, с учётом регистра и пунктуации, после NFC и нормализации пробелов. Похожие буквы разных алфавитов не объединяются. Raw CER сохраняет порядок, который вернул движок. Content CER сопоставляет регионы/слова с эталонными координатами и собирает фрагменты каждой строки по X; это диагностическая метрика, результат OCR она не исправляет. У Windows используются координаты слов, поскольку API может разрезать одну строку на несколько или объединить части. Порог сопоставления — 35% площади обнаруженного региона.

Working set снимается через Windows GetProcessMemoryInfo с ОС-счётчиком пика; private bytes семплируются каждые 20 мс и при выводе результата. У Windows также есть собственные снимки памяти из процесса. **Это память целого тестового процесса:** Windows включает PowerShell/WinRT wrapper, pure включает Rust executable и engine. Эти числа нельзя выдавать за добавочную RAM внутри WPF-приложения. Внешний startup Windows включает PowerShell; для сравнения задержки движков используйте engine load/first/repeated, а не только запуск оболочки.

Один и тот же движок выдавал одинаковый текст, геометрию и confidence во всех пяти проходах каждого PNG. Пиковое время первого прохода: Windows 69,4 мс, pure 1031,6 мс. Начальная компиляция прототипа заняла 7 минут 26 секунд и не включается во время OCR.

Для двух колонок эталон читает левую сверху вниз, затем правую. pure правильно распознал все 16 строк, но вернул порядок индексов `[4,0,1,5,2,6,3,7]`: raw CER 49,36%, content CER 0%. Windows прочитал колонки последовательно. Его две ошибки порядка относятся к русскому Consolas 18 px: API разрезал строки и сначала вывел левые фрагменты, затем правые; raw CER там 49,50%, content CER 17,26%. Простая сортировка всех регионов по Y не решает чтение отдельных колонок.

В смешанном тексте pure допускает особенно неприятные ошибки: эталон `CopyBuffalo` превращается в `СоруBuffalo`, где первые четыре символа кириллические, а `image_2026.png` — в `imаgе_2026.png` с кириллическими а/е. Внешне такой текст похож на правильный, но идентификаторы и пути отличаются. Именно поэтому Unicode-сравнение не заменялось визуальной оценкой и результат нельзя считать гарантированно пригодным для команд.

Рекомендация: продолжить рассматривать связку для локального извлечения текста по запросу, особенно русского текста и мелкого шрифта. Она подтверждённо работает без ручной конвертации моделей/словаря, её задержка порядка 0,4 с при повторном проходе и RAM порядка 0,1–0,14 ГиБ приемлемы для этого железа. Для внедрения ещё нужна отдельная проверка сложных layout и смешанных идентификаторов; выбор Windows OCR остаётся привлекательным по задержке и доступности встроенного API. Прототип Rust возвращает JSON, готовых .NET bindings в проведённой проверке нет. Размер тестового exe — 28,2 МиБ, ONNX моделей — 12,3 МиБ; это не изменение установщика CopyBuffalo.

Все зависимости и артефакты остаются локальными для прототипа. Полная инструкция — README в архиве.

Сырые результаты: `.tmp/ocr-study-20261011/results/windows.json`, `pure.json`, `scored.json`, `per-case.csv`. Они и полный синтетический корпус включены в архив. Scorer проверен assert-тестами на вставку, удаление, замену, пропуск строки, инверсию порядка и сопоставление WinRT-слов.

Не проверены: сравнение с отсутствующим OCR CopyBuffalo; GPU/CUDA или альтернативный ONNX Runtime; PP-OCRv6 на изображениях; реальные интерфейсы, ClearType со снятого экрана, масштабы DPI, blur/компрессия/низкий контраст/вращение; большие страницы и долгоживущий кеш на разных размерах; интеграция, live UI, clipboard, установщик и добавочная RAM WPF-приложения. Рабочая реализация и чужие изменения не затронуты.
