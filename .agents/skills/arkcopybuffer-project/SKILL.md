Work from the repository root. This is a Windows-only .NET 10 WPF clipboard-history app (Windows 10 1809+ / Windows 11, Intel/AMD x64). `WinVHook.cs` handles Win+V; `ClipboardWatcher.cs` captures clipboard changes; `HistoryStore.cs` persists entries; `Paster.cs` restores and pastes them; `PanelWindow.xaml` / `.xaml.cs` render the panel; `App.xaml.cs` wires these parts together, owns the tray menu, and stores settings under `HKCU\Software\ArkCopyBuffer`.

- Keep clipboard capture and panel opening responsive. Check image dimensions before decoding; keep large file and encryption work off the UI thread. Preserve WPF dispatcher ownership and the foreground-target checks before simulated input.
- Preserve the current record-time display unless the user explicitly asks to change it.
- Runtime data lives in `%LOCALAPPDATA%\ArkCopyBuffer`: encrypted `history.dat`, encrypted `images\`, and `symbols.json`. Do not use real history as test data or remove it during cleanup. Diagnostic files there include `error.log`, optional `trace.log`, and `selftest.log`.
- Folder FileDrop entries use `MediaKind="folder"` with the original path in `Text`, no stored contents or `ImageHash`. `FolderArchive.cs` streams a fresh ZIP on demand; `Paster` puts it in the existing temporary-file area and marks its FileDrop with the folder entry Id. Keep cancellation, partial-file cleanup, reparse-point rejection, disk-space checks and the original-target guard. Folder references use ordinary history retention, and missing folders remain as references so disconnected drives can return.
- `UnrealGraph.cs` parses Unreal material/Blueprint text and Unity **Shader Graph** copy data, draws graph previews, and opens the full viewer. Unity Visual Scripting is a separate clipboard mechanism and is not supported by this parser. Keep graph previews off the UI thread (`IsAsync=True` binding); freeze shared WPF brushes and the completed `DrawingImage` before crossing threads. The full viewer uses a `Canvas` so the image receives its full natural size before pan/zoom and viewport clipping.
- `PromptCompressor.cs` backs the text-item menu entry «Сжать промпт»: it lazily starts `llama-server` (paths from registry `LlamaServer` / `LlamaModel`, else PATH and `%LOCALAPPDATA%\ArkCopyBuffer\models\Qwen3.5-4B-Q4_K_M.gguf`) inside a kill-on-close Job Object, disables Qwen thinking per request, rejects `finish_reason=length`, and kills the server right after each compression (the user wants no resident model; ~3 s cold start is accepted). It runs `llama-server` with `--no-cache-prompt -ctxcp 0` (checkpoint restore crashed b9728 with CUDA illegal memory access on hybrid Qwen3.5) and retries once if the server dies mid-request. The system prompt and the two per-language few-shot examples were tuned on Qwen3.5-4B with greedy decoding; retune with the local, gitignored scorer `.tmp/llm/evalc.py` (must-keep facts per sample, including held-out dictated samples) and never add the test samples themselves as examples. The result goes through `HistoryStore.Add` and `Paster.CopyText`. Check VRAM with `nvidia-smi` before running the model.

Alt key-down cancels existing previews/GIF playback.
